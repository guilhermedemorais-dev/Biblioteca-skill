# Phase specification

Use one module task with internal phases. Add page and component specs where needed.

| Section | Record |
|---|---|
| Identity | Module, phase, revision, approved PRD, matching Discovery and architecture revisions |
| Scope | Goal, deliverables, exclusions, dependencies, allowed and protected paths, stop conditions |
| Behavior | Actors, permissions, inputs, preconditions, normal and failure flows, states, outputs and postconditions |
| Contracts | Data, migrations, API, UI and integrations as applicable, with compatibility and rollback |
| Controls | Security, observability, measurable quality attributes and risks; justify omissions |
| Traceability | For each REQ, cite approved source/evidence and link MT, AC and TEST IDs |
| Validation | Expected outcomes, negative and regression cases, commands or manual procedure, independent reviewers |
| Readiness | Open decisions, QA verdict on matching revisions, human approval |

Use the project task schema for IDs and test definitions. Discovery observations support requirements within approved scope. Keep UNKNOWN unresolved.
