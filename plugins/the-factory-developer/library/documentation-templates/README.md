# Documentation templates and source metadata

These are original reusable structures, not copied vendor articles. Choose only the form the implemented product needs. The Documentation owner verifies behavior against the target product; templates establish no product facts.

| ID | Template | Purpose |
| --- | --- | --- |
| DOC-TUTORIAL | `tutorial.md` | Guided learning with a real fixture and observed result |
| DOC-HOWTO | `how-to.md` | Complete a specific task with prerequisites and recovery |
| DOC-REFERENCE | `reference.md` | Exact interface, field, permission and error semantics |
| DOC-EXPLANATION | `explanation.md` | Explain current architecture and decisions |
| DOC-VISUAL | `visual-evidence.md` | Capture provenance and redaction/caption requirements |

## Verified references

Checked 2026-10-16 through official pages. Diátaxis identifies tutorials, how-to guides, reference and explanation as distinct needs: https://diataxis.fr/ . Microsoft lists concise instructions, numbered procedures and media alternatives and recommends documenting supported interactions: https://learn.microsoft.com/en-us/style-guide/procedures-instructions/ . Docusaurus documents rendering hierarchical Markdown documentation: https://docusaurus.io/docs/docs-introduction . These support structure, not the behavior of a client application. No Docusaurus dependency is introduced.
